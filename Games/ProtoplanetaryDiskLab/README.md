# Protoplanetary Disk Lab

Интерактивная браузерная мини-лаборатория для образовательной симуляции формирования протопланетного диска и аккреции планет.

> **Важно:** это упрощённая образовательная модель, а не точная астрофизическая симуляция. Все приближения и художественные упрощения описаны ниже.

## Запуск

```bash
cd Games/ProtoplanetaryDiskLab
npm install
npm run dev
```

Откройте в браузере адрес, который выведет Vite (по умолчанию `http://localhost:5175`).

Сборка:

```bash
npm run build
npm run preview
```

├── state/

Модули разделены так, чтобы физические модели, рендеринг и анализ данных можно было заменять независимо.

## Режимы физики

| Режим | Описание |
|-------|----------|
| **1 — Визуальная демонстрация** | Кеплеровские орбиты, дисперсия скоростей, формирование диска |
| **2 — Упрощённая физика** | Гравитация звезды, взаимодействие крупных тел, столкновения, слипание |
| **3 — Экспериментальный N-body** | Попарная гравитация для малого числа объектов; предупреждение о нестабильности |

## Физические приближения и ограничения

- Единая центральная звезда с точечной гравитацией (без релятивистских и квадрупольных эффектов).
- Нет газовой динамики, магнитных полей, излучательного давления.
- Столкновения — сферические тела с упрощённым правилом слипания/отскока.
- Плотность материала постоянна внутри типа (пыль, камень, лёд, металл).
- Угловой момент и энергия **не сохраняются точно** из-за дискретизации и упрощённых столкновений — дрейф отображается на графиках.
- Визуальный радиус отделён от физического (мелкие тела иначе невидимы).
- Режим 1 не претендует на физическую корректность — только наглядность.
- N-body режим ограничен по числу объектов из соображений производительности.

## Фазовое пространство

Полная система из N тел имеет фазовое пространство размерности 6N (положение + скорость для каждого тела). Это слишком много для прямой визуализации.

В панели **Phase Space** показаны **двумерные проекции** состояний отдельных объектов:

- `r — vᵣ` (радиус и радиальная скорость)
- `r — vₜ` (радиус и тангенциальная скорость)
- `x — vₓ`
- угловой момент — энергия
- большая полуось — эксцентриситет
- масса — орбитальная энергия

Одна точка на графике — **не** вся система, а проекция одного объекта.

## Фазовое vs латентное пространство

| | Фазовое пространство | Латентное пространство |
|--|---------------------|------------------------|
| Задаётся | Физическими переменными (q, p, m…) | Выученным/сконструированным сжатием |
| Размерность | 6N (огромная) | Мала (2–3 для визуализации) |
| Интерпретация | Прямая физическая | Зависит от метода (PCA, автоэнкодер…) |

Вкладка **State-Space Explorer** применяет PCA к вектору агрегированных признаков системы (число объектов, распределения масс, энергия, угловой момент и т.д.) и показывает траекторию эволюции в сжатом пространстве. Это **аналогия**, а не тождество с фазовым пространством.

## Производительность

- Цель: ≥30 FPS при нескольких тысячах визуальных частиц.
- Instanced rendering для частиц (отдельные mesh на объект; оптимизация instancing — в планах).
- Spatial hashing для столкновений.
- Три уровня качества: Low / Medium / High.
- Автоснижение качества при FPS < 25.
- Отображение FPS и времени физического шага.

## Известные ограничения

- Нет Web Worker для физики (планируется).
- Instanced rendering не полностью оптимизирован — при >3000 частиц возможно падение FPS.
- Barnes–Hut не реализован (только spatial hash + ограничение N-body).
- Следы орбит в 3D не реализованы (есть в фазовом пространстве).
- Эффекты столкновений минимальны.
- Режим 3 может быть численно нестабилен при большом шаге.
